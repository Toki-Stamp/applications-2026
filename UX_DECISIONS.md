# Принятые решения по UX и бизнес-логике (UX Decisions)

В этом документе фиксируются неочевидные, но намеренные решения в поведении интерфейса и бизнес-логике, чтобы разработчики (включая ИИ-ассистентов) не пытались "исправить" их, принимая за баги.

## 1. Навигация по шагам (NavigationButtons)

- **Отсутствие кнопки "Назад" на шаге 2 (Формат участия):**
  Шаг 1 является вступительным (Intro), по сути, обложкой или лендингом. Как только пользователь нажимает "Начать заполнение" и переходит на Шаг 2 (первый реальный шаг формы), возможность вернуться на обложку блокируется. Кнопка "Назад" намеренно скрыта на Шаге 2 (`currentStep > 2`), чтобы фокус пользователя оставался на заполнении формы.

## 2. Валидация полей (Validation)

- **Отложенная валидация (Lazy Validation):**
  Поля формы не должны подсвечиваться красным сразу при появлении на экране. Ошибка "Это поле обязательно" появляется только после того, как пользователь попытался взаимодействовать с полем (флаг `isTouched`) или нажал кнопку "Далее" (`forceTouch`).
- **Перехват потери фокуса (`focusout`):**
  Чтобы исключить баги рассинхронизации состояния (когда красная обводка осталась, а кнопка "Далее" разблокировалась), форма пересчитывает ошибки при событии `focusout`. Однако этот обработчик строго отфильтрован и срабатывает **только** при потере фокуса с полей ввода (`INPUT`, `TEXTAREA`, `SELECT`, `MD-*`). Он не должен срабатывать при кликах на кнопки навигации, иначе возникает бесконечный цикл валидации и мерцание интерфейса.

## 3. Обработка фантомных ошибок (Race Conditions)

- Компоненты, такие как `TransportBlock`, могут динамически скрывать и показывать внутренние поля (например, "Количество свободных мест" появляется только если выбран водитель). При скрытии полей компонент **обязан** переопределять их значения по умолчанию, чтобы валидатор не ругался на невидимые поля. Svelte-стор `$formStore` используется как единственный источник истины.

## 4. Транспортировка (Бизнес-логика)

- **Опция "Как водитель" для обратной дороги:** Доступна только в том случае, если для дороги "ТУДА" также была выбрана опция "Как водитель". Если пользователь изначально выбрал "Как водитель" в обе стороны, а затем изменил способ прибытия на базу, выбор для обратной дороги автоматически сбрасывается, чтобы предотвратить невалидное состояние.

## 5. Оптимизация иконкового компонента (ADR-001)

- **Отказ от монолитного WOFF2-шрифта Material Symbols (3.96 МБ):**
  Полный шрифт `material-symbols-outlined.woff2` от Google весит около 4 МБ, что сильно замедляет первоначальную загрузку приложения. Проект переведён на изоляцию SVG-векторов через компонент `<md-icon>`.
- **Сохранение API и стилизации:**
  Использование синтаксиса `<md-icon>icon_name</md-icon>` и возможность гибкого управления всеми CSS-стилями (`color`, `font-size`, `fill: currentColor`) полностью сохранены.
- **Инструкция по добавлению новых иконок:**
  Все используемые иконки хранятся в `src/assets/icons/`. Инструкция для ИИ-агентов по вызову `npm run fetch-icon <name>` зафиксирована в [`AGENTS.md`](file:///d:/Projects/Google%20Antigravity/Applications-2026/AGENTS.md).
